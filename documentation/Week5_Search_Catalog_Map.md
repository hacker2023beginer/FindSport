## 2. Сверка поисковых полей и фильтров с ТЗ (PM, п. 1–3 плана)

### 2.1. Поля, охватываемые поиском (ТЗ п. 4.7.1)

| Поле ТЗ | Мероприятие | Организация / тренер |
|---|---|---|
| Наименование | `title_ru`, `title_en` | `name_ru`, `name_en` |
| Описание | `description_ru`, `description_en` | `description_ru`, `description_en` |
| Виды спорта | `event_sport` → `sport.name_ru`, `sport.name_en` | `provider_sport` → `sport.name_ru`, `sport.name_en` |
| Населенные пункты | `address.locality` | `address.locality` |
| Адреса | `address.street`, `address.district` | `address.street`, `address.district` |

Регистронезависимость и частичное совпадение (п. 4.7.4) обеспечиваются конструкцией
`lower(col) LIKE '%запрос%'` и индексами GIN `gin_trgm_ops`, созданными миграциями
`V3`, `V7` (поставщики) и `V8` (новые столбцы).

### 2.2. Фильтры (ТЗ п. 4.7.2, п. 4.9.4)

| Фильтр ТЗ | Параметр API | Применимость |
|---|---|---|
| Область | `regionId` | Мероприятия и поставщики |
| Город | `city` | Мероприятия и поставщики |
| Вид спорта | `sportId` | Мероприятия и поставщики |
| Возраст | `age` | Только мероприятия (п. 4.9.4) |
| Цена | `priceMin`, `priceMax` | Только мероприятия (п. 4.9.4) |
| Дата | `dateFrom`, `dateTo` | Только мероприятия (п. 4.9.4) |
| Формат | `format` | Только мероприятия (п. 4.9.4) |
| Наличие свободных мест | `hasFreeSeats` | Только мероприятия (п. 4.7.2) |
| Тип объекта | `type` (EVENT, ORGANIZATION, TRAINER) | Все типы |

**Решение PM:** фильтр, применимый только к мероприятиям (возраст, цена, дата, формат, свободные
места), исключает карточки поставщиков из выдачи: в профиле организации или тренера таких сведений нет
(п. 4.10.4, 5.2), и показывать их в выдаче с примененным фильтром означало бы вводить посетителя
в заблуждение. Счетчики панели фильтров показывают то же, что вернет выдача.

### 2.3. Сортировка и постраничный вывод

| Вариант | Параметр `sort` | Основание |
|---|---|---|
| По новизне (по умолчанию) | `NEWEST` | ТЗ п. 4.7.3 |
| По дате проведения | `DATE` | ТЗ п. 4.9.1 — раздел мероприятий по дате |
| По цене | `PRICE` | ТЗ п. 4.7.2 — фильтр по цене поддержан, порядок по цене дополняет его |

Общее число найденного и число страниц возвращаются вместе с выдачей (п. 4.7.7–4.7.8).

### 2.4. Понятность каталога и карточек (PM, п. 3 плана)

Панель фильтров вынесена в левую колонку и содержит счетчики по типам объектов и видам спорта —
посетитель до применения фильтров видит, сколько объектов доступно. Примененные фильтры
выводятся «плашками» со снятием по одному, рядом — ссылка на результат с параметрами в URL
(п. 4.7.9). Карточка мероприятия сохраняет параметры поиска и предлагает вернуться к выдаче
(п. 4.3.5). Сортировка вынесена в заголовок выдачи — текущий порядок виден постоянно.

## 3. Контрольные примеры поиска (PM, п. 2 плана)

Примеры зафиксированы в `CatalogApiIntegrationTests` и служат критерием приемки.

| № | Условие | Ожидаемый результат |

| 2 | `q=ПОЛУМАРАФОН` | То же, что в п. 1: регистр не влияет (п. 4.7.4) |
| 3 | `q=мараф` | То же, что в п. 1: совпадение частичное (п. 4.7.4) |
| 4 | `q=по плаванию` | Найдено только «Гомельский турнир» — поиск по описанию |
| 5 | `q=Старт` | Найден только профиль «Беговой клуб «Старт»» — поиск по поставщикам (п. 4.10.3) |
| 6 | `q=плавание` | Найдено «Гомельский турнир» — поиск по названию вида спорта (п. 4.7.1) |
| 7 | `q=100%` | Ничего не найдено, ошибки нет: спецсимволы шаблона экранированы |
| 8 | `regionId` + `city` + `sportId` + `age` + `priceMax` + `dateFrom` + `dateTo` + `hasFreeSeats` | Найдено только «Минский полумарафон»: фильтры применяются совместно (п. 4.7.2) |

## 5. Проверка скорости на подготовленных данных (QA, п. 8 плана)

Подготовка данных (генератор включен только по явному признаку):

```
docker compose up -d
java -jar target/findsport-0.0.1-SNAPSHOT.jar \
  --spring.datasource.url=jdbc:postgresql://localhost:5432/findsport \
  --spring.datasource.username=findsport --spring.datasource.password=findsport_dev \
  --spring.mail.host=localhost --spring.mail.port=1025 \
  --findsport.tools.seed.enabled=true --findsport.tools.seed.events=2000 \
  --findsport.tools.seed.providers=20
```

Результаты на наборе из 2000 опубликованных мероприятий и 20 профилей поставщиков
(время ответа API, локальная среда, PostgreSQL 17 в Docker):

| Запрос | Результат |
|---|---|
| `GET /api/v1/catalog?size=1` (общий счетчик) | 2020 объектов, 2020 страниц при размере 1 |
| `GET /api/v1/catalog?q=забег&size=20` (текстовый поиск) | 71 мс |
| `GET /api/v1/catalog?city=Минск&sort=DATE&size=20` (фильтры и сортировка) | 42 мс |
| `GET /api/v1/catalog/map` (2000 меток) | 2000 меток с координатами населенных пунктов |

Целевое значение ТЗ п. 4.12.5 — не более 2 секунд для 95 % обычных запросов; фактические
значения укладываются в него с большим запасом. Полная нагрузочная проверка относится
к приемочным испытаниям этапа (п. 6.8), предварительная — в пределах недели 5.

## 6. Наполнение тестового каталога (PM, п. 4 плана)

Генератор `SyntheticDataGenerator` создает спортивный словарь, 20 профилей поставщиков
и заданное число опубликованных мероприятий с адресами из справочника населенных пунктов,
датами в ближайшие 120 дней, предложениями с ценами и лимитами участников. Генератор
выключен по умолчанию: он включается только признаком `findsport.tools.seed.enabled=true`
(раздел 5) и не влияет на обычную работу приложения.

## 7. Решения недели

1. **Координаты карты берутся из населенного пункта адреса.** Адрес карточки по ТЗ п. 7.6
   координат не содержит, поэтому введен справочник `locality` с координатами 34 населенных
   пунктов и резервные координаты центра области. Метка карты соответствует месту проведения
   с точностью до населенного пункта.
2. **Карта реализована собственной схемой (SVG), без внешних сервисов.** Внешние картографические
   сервисы в объем работ не входят (ТЗ п. 8.6 — внешние интеграции как последующее развитие),
   поэтому контур Беларуси хранится локально в `static/geo/belarus-outline.json`.
3. **Выдача каталога собирается одним SQL-запросом с объединением ветвей.** Разные типы объектов
   нельзя объединить через JPA, а постраничный вывод и общее число найденного требуют единого
   упорядочивания — иначе счетчик и страницы расходились бы с выдачей.
4. **Добавлена публичная карточка поставщика** `/provider-card.html`: без нее карточки
   организаций и тренеров из каталога не открывались.
